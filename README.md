# Trip Together — 우리들의 오사카

5명이 여행 후보를 모으고, 투표한 뒤 직접 일정을 확정하는 **모바일 우선 HTML 프로토타입**입니다.
여행 날짜는 **2026년 11월 6일~8일**, 참여자는 **5명**으로 구성했습니다. 실제 여행 일정은 임의로 만들지 않았습니다.

## 바로 열기

`index.html`을 브라우저에서 열면 됩니다. 일반 사용에는 설치나 빌드가 필요하지 않습니다.

GitHub Pages 배포 주소:

`https://cafesowoo.github.io/osaka-trip-board/`

```sh
open index.html
```

CSS와 앱 코드는 HTML 안에 포함되어 있습니다. 웹 폰트를 불러오지 못하면 시스템 폰트를 사용합니다.
후보·투표·댓글·설정은 인터넷 없이도 작동합니다. 외부 지도·사진·길찾기에는 인터넷 연결이 필요합니다.

## 중요한 범위

**현재는 실시간 공동 편집 서비스가 아닙니다.** 데이터는 현재 브라우저의 localStorage에 저장됩니다.
다른 사람의 휴대폰이나 다른 브라우저로 자동 전송되지 않습니다. 같은 브라우저의 같은 주소로 연 탭 사이에는 변경 내용을 반영하지만, 이것은 5인 온라인 동기화와 다릅니다.

참여자 선택은 기능을 체험하기 위한 이름 전환입니다. 로그인·본인 인증·접근 제어가 아닙니다.
현재 참여자를 바꾸면 다른 사람의 이름으로도 투표할 수 있으므로, 공개 서비스로 쓰기 전에는 인증과 서버 측 권한 검사가 필요합니다.

파일 이동, 브라우저 변경, 시크릿 모드, 저장소 삭제 등에 따라 기존 데이터가 보이지 않을 수 있습니다.
중요한 내용은 설정에서 **JSON 백업**을 다운로드해 보관하세요. 가져오기는 **전체 교체**이며 병합되지 않습니다.

## 사용 흐름

1. 상단에서 참여자를 선택합니다. 설정에서 5명의 이름을 바꿀 수 있습니다.
2. 날짜를 선택하고, 시간대의 `+` 또는 하단 중앙 `+`를 눌러 후보를 남깁니다.
3. 장소명과 카테고리, Google 지도 링크를 입력합니다. 비용·체류시간·메모·사진·좌표 등은 선택사항입니다.
4. 마음에 드는 여러 후보에 투표합니다. 같은 후보에는 한 사람당 한 표이며 다시 누르면 취소됩니다.
5. 후보 제목을 눌러 댓글을 남기거나 `이 일정으로 확정`을 선택합니다. 투표 1위가 자동으로 확정되지는 않습니다.
6. 지도 탭에서 확정 일정 또는 미확정 시간대의 상위 후보까지 함께 확인합니다.

처음에는 빈 보드가 표시됩니다. **샘플로 둘러보기**는 별도의 체험 화면이며 실제 보드의 데이터를 덮어쓰지 않습니다.
샘플의 장소·위치·비용·투표는 기능 설명을 위한 예시이며 실제 추천 일정이나 검증된 여행 정보가 아닙니다.

## 구현된 기능

### 날짜별 일정 보드

하루 8개 시간대: 아침식사, 오전 일정, 점심식사, 오후 일정 ①·②, 저녁식사, 저녁 일정 ①·②.
각 날짜에서 시간대를 켜고 끄거나 시작·종료 시간을 바꿀 수 있습니다. 시간대를 꺼도 후보는 삭제되지 않습니다.
시간은 일본 현지 시각으로 입력합니다. 자정을 넘는 시간 범위는 다음 날짜로 나누어 입력해야 합니다.

`후보 모집 중 → 투표 중 → 일정 확정` 상태를 설정합니다. 사용하는 모든 시간대에 선택된 일정이 있어야 확정 상태로 바꿀 수 있습니다.
확정된 선택을 해제해 빈 시간대가 생기면 투표 중으로 돌아갑니다.
날짜 잠금은 해당 날짜의 후보 등록·수정·삭제, 투표, PICK, 댓글, 확정 및 시간대 변경을 막습니다. 잠금은 어느 참여자든 해제할 수 있는 실수 방지 기능이지 보안 권한이 아닙니다.

### 후보 · 투표

장소명, 지도 링크, 카테고리, 주소, 설명, 1인 예상 비용(엔), 체류시간(분), 예약 필요 여부, 실내/야외/날씨 무관 태그, 사진 URL, 좌표를 저장합니다.
카테고리는 식사·카페·관광·쇼핑·놀거리·술·야경·기타입니다. 사진은 URL 방식이며 파일 업로드는 없습니다.

투표자는 이름으로 표시됩니다. 같은 날짜·시간대 안에서 표 수순으로 정렬하고, 동률은 공동 순위로 표시합니다(예: 1위·1위·3위). 0표에는 순위를 붙이지 않습니다.
상위 3개 이후 후보는 펼쳐볼 수 있으며, 최종 선택된 후보는 별도 영역에 표시합니다.
**PICK은 사람당 여행 전체에서 최대 3개**입니다. 일반 투표와 별도로 취소할 수 있습니다.
후보 제안자만 그 후보의 수정·삭제 버튼을 볼 수 있습니다. 실제 온라인 서비스에 필요한 보안은 별도 구현해야 합니다.

### 댓글 · 우천 대안 · 비용

후보별 댓글을 저장합니다. 댓글과 제목은 HTML로 실행되지 않도록 처리합니다.
같은 시간대의 다른 후보를 우천 대안으로 지정할 수 있습니다.
예상 비용은 사용 중인 시간대의 확정 후보만 합산합니다. 미입력 비용은 0원/무료로 단정하지 않고 개수를 따로 표시합니다.
교통·항공·숙박비는 자동 합산하지 않습니다. 항공편·숙소 정보는 별도의 메모로 저장합니다.

### 지도 · 동선

Google 지도 검색을 새 창으로 열고, 장소의 공유 링크를 붙여넣는 방식입니다. 장소명 기반 검색 링크도 생성할 수 있습니다.
**Google Places 자동 완성, 주소·평점·사진 자동 수집은 연결되어 있지 않습니다.**

전체 지도는 Leaflet 1.9.4와 OpenStreetMap 배경 지도를 사용합니다. 좌표가 있는 일정만 핀으로 표시하며, 좌표가 없는 곳은 목록에 남겨 둡니다.
장소 좌표(`!3d…!4d…` 또는 좌표 검색 query)가 들어 있는 Google 링크에서만 좌표를 추출합니다.
짧은 공유 링크는 확장하지 않으며 `@위도,경도` 형식의 화면 중심 좌표를 장소의 정확한 좌표로 오인하지 않습니다.
좌표는 후보 수정의 선택 항목에서 직접 입력할 수 있습니다.

핀 사이 점선은 방문 순서이지 실제 도로 경로가 아닙니다. 좌표가 없는 중간 후보를 건너뛰어 선을 잇지 않습니다.
구간별 Google 길찾기는 대중교통·도보·자동차로 연결됩니다. **자동 이동시간 계산은 없으며**, 실제 시간은 Google 지도에서 확인합니다.
사용자가 확인한 이동 메모를 각 시간대에 적을 수 있습니다.
미확정 시간대의 상위 후보 보기는 1표 이상 받은 후보만 포함하고, 동률이면 먼저 등록된 후보를 대표로 표시합니다.

### 저장 · 보호

localStorage 키: `trip-together.osaka.2026.v1`.
현재 선택한 참여자는 탭의 sessionStorage에 저장합니다.
저장 실패 시 경고하고, 잘못된 기존 JSON을 발견하면 원본을 덮어쓰지 않고 다운로드할 수 있게 합니다.
같은 브라우저의 다른 탭에서 수정 중인 경우, 오래된 입력 화면이 새 데이터를 덮어쓰지 않도록 검사합니다.
백업 가져오기는 구조·URL·참여자·투표·확정 참조를 검사한 뒤 확인을 받습니다. 최대 파일 크기는 3MB입니다.

사진 URL의 서버, 지도 제공자 및 웹 폰트 제공자에게는 해당 리소스를 읽는 브라우저 요청이 전송됩니다.
백업 파일에는 참여자 이름·댓글·예약 메모가 포함되므로 민감한 예약번호나 신분정보는 기록하지 않는 것이 좋습니다.

## 개발 및 검사

```sh
# src 변경 후 단일 HTML 다시 생성
node build.mjs

# 상태 모델 검사
node --test tests/model.test.mjs

# 선택 사항: 실제 Chrome 브라우저 자동 검사 도구 설치
npm install --prefix .qa --no-audit --no-fund playwright@1.55.1

# 별도 터미널에서 이 폴더만 로컬로 제공
python3 -m http.server 8914 --bind 127.0.0.1

# 브라우저 검사: 사용자의 일반 Chrome 프로필과 분리해서 실행
node qa/browser-check.cjs
```

`CHROME_BIN` 환경변수로 Chrome 실행 파일을, `TRIP_TEST_URL`로 검사 주소를 지정할 수 있습니다.
`.qa/`에는 검사 전용 의존성이 있고, `qa-output/`에는 검사 결과·스크린샷이 저장됩니다. 둘 다 이 폴더의 `.gitignore`에서 제외합니다.

## 파일 구성

```text
index.html             바로 열 수 있는 단일 HTML
src/shell.html         문서 구조
src/style.css          반응형 스타일
src/model.js           데이터 검증·투표·확정·잠금 규칙
src/app.js             화면·입력·저장·지도 연결
build.mjs              단일 HTML 생성
tests/model.test.mjs   상태 모델 자동 검사
qa/browser-check.cjs  실제 브라우저 사용 흐름 검사
```

다음 개발 단계는 공용 데이터베이스, 초대/로그인, 서버 측 투표 중복 및 권한 검사, 실시간 동기화, Google Places 연동입니다.
이 버전에서는 Supabase나 기존 프로젝트의 데이터베이스를 생성·변경하지 않았습니다.
